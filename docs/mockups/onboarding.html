Step 1 of 5

Let your AI tools use websites, not your passwords

siteadapter runs small adapters for sites without a public API, like Woolworths, and offers their tools to Claude over MCP. It runs on this Mac only: no account, no cloud.

Adapters never see a password
Logins run in a separate session from 1Password. Adapter code never runs there, and gets a logged-in page afterwards.
Only declared hosts
Every request an adapter makes is checked against the hosts and API calls it declared and you approved.
Nothing irreversible without you
Checkout, payment and the like wait for your confirmation in this app. An agent can't give it.

Step 4 of 5 · optional

Text-message codes

Some sites text you a code when you log in. siteadapter can read it from Messages so the login finishes without you. It needs more access than that sounds like, so skipping is fine.

What it needs: Full Disk Access
macOS has no permission for Messages alone. Full Disk Access lets siteadapter read any file you can, including mail, photos and documents. You'd be trusting the siteadapter app with all of it, not just your texts.
What siteadapter does with it
  • Reads Messages only when a login step asks for a code
  • Only recent texts matching the adapter's sender and pattern
  • Types the code into the site; adapters and agents never see it, and it isn't logged
Woolworths doesn't need it today. No text-message code has been seen on its login. An adapter that wants codes says so in its manifest, and its review shows it. Turn this on later in System Settings › Privacy & Security › Full Disk Access.
You can turn it off there any time.
